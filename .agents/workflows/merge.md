# Branch Merge & Sync Planner (日本語)

**トリガー:** `/merge`

**説明:**
GitHub上のプルリクエスト（PR）をマージし、ローカルの `main` ブランチを最新化して作業ブランチ（`dev` 等）と同期するためのコマンドを立案・提示します。
PRを作成した後の標準的なマージ・同期手順として、`gh pr merge` を使用するパターンを基本的に提案します。

> **⚠️ 注意:**
> エージェント環境（サンドボックス）では `gh` や `git merge` 等の権限やネットワークが制限されているため、**エージェント自身はマージを実行せず、ユーザーにコピー＆ペースト用のコマンドブロックを提示します。**

---

## 1. 現状分析
- **目的:** 現在のブランチ名、作業ツリーの状態、および関連するPR情報を確認する。
- **アクション:**
  - `git status` で作業ツリーがクリーンであることを確認する（未コミットの変更がある場合は、まずコミットまたは退避を促す）。
  - `git branch` で現在のブランチ名（`dev` や `feature/*` 等）を把握する。
  - 会話履歴や直前のコンテキストから、対応する PR 番号（例: `#18` 等）を特定する。

## 2. マージ＆同期コマンドの提示（ユーザー実行依頼）
- **目的:** ユーザーが自身のターミナルで安全にマージとローカル同期を実行できるようにする。
- **出力フォーマットの厳守ルール:**
  - **コマンドの解説・意図:** 必ずマークダウン本文に記述する。各ステップの目的を明確に説明する。
  - **コピペ用コードブロック (```bash):** コメント行（`# ...`）を含めず、純粋に実行可能なコマンドのみを記載する（zsh 等の誤認識エラーを防止するため）。

### 基本提案パターン（gh pr merge によるPRマージとローカル同期）
PR番号が特定できている場合はその番号、特定できない場合はブランチ名またはプレースホルダーを指定した以下の形式を基本的に提示する：

1. `gh pr merge <PR番号> --merge`（または `gh pr merge <対象ブランチ> --merge`）
2. `git checkout main`
3. `git pull origin main`
4. `git checkout <対象ブランチ>`

※対象ブランチが使い捨ての feature ブランチであり、削除したい場合は `gh pr merge --delete-branch` および `git branch -d <対象ブランチ>` を案内する。`dev` 等の常設ブランチの場合はブランチを維持して戻る。

### 代替パターン（ローカル直接マージ）
PR を経由せずローカルで直接マージしたい場合（緊急対応や1人開発等）の代替手段として、以下も必要に応じて併記する：

1. `git checkout main`
2. `git pull origin main`
3. `git merge <対象ブランチ> --no-ff -m "Merge branch '<対象ブランチ>' into main"`
4. `git push origin main`
5. `git checkout <対象ブランチ>`

ユーザーに対し、提示したコマンドをターミナルにコピー＆ペーストして実行するよう依頼して終了する。
