# 教材記事執筆スキル

**トリガー:** 教材記事の本文・リード文・学習目標・見出し・ロードマップ・README・記事メタデータ（`description`）を書く、または書き換えるとき。

**目的:** 読者が「誰が・何を・どうする話なのか」を文面だけで再現・検算できる文章にする。雰囲気で伝わった気にさせる表現を書かない。

---

## 1. 大原則

1. **すべての文は数学的な事実か操作を述べる。** 「何に何をすると何になるか」を主語・対象・結果まで書く。
2. **比喩で説明しない。** 比喩を使うと、読者は比喩の意味を推測する作業を強いられる。数学用語と式で直接書く。
3. **誇張しない。** 効果は数値・回数・式で示す。形容詞で盛らない。
4. **具体例を必ず付ける。** 一般論の直後に、実際の数値で計算した例を置き、読者が手で検算できるようにする。
5. **新しい用語は、使う前に定義する。** 定義は式で書く（例: 「\( A\vec{v} = \lambda\vec{v} \)（\( \vec{v} \neq \vec{0} \)）を満たす \( \vec{v} \) を固有ベクトルと呼ぶ」）。
6. **「係数」「成分」「座標」「表現行列」を書くときは、基底を必ず明記する。** ベクトルそのもの（幾何学的対象）と、特定の基底で測った数値の組（成分・係数）を混同させない。単に「\( A\vec{x} \) の係数」と書かず、「固有ベクトル \( \vec{v}_1, \dots, \vec{v}_n \) を基底として \( A\vec{x} \) を表したときの係数」のように、何を基準にした数値なのかを必ず明記する。

## 2. 禁止表現

次の表現は使わない。見つけたら「書き換え方」に従って直す。

| 種類 | 禁止例 | 問題点 | 書き換え方 |
| :--- | :--- | :--- | :--- |
| 擬人化・視点の比喩 | 観察する、見つめ直す、〜から見ると、〜の目線で | 誰がどこから見ているのか不明 | 「〜を基底にして成分を表すと」「〜の係数は」 |
| 移動の比喩 | 乗り換える、旅する、たどり着く | 実際の操作が書かれていない | 「基底を \( \vec{v}_1, \vec{v}_2 \) に取り替える」「\( \vec{c} = P^{-1}\vec{x} \) で係数を求める」 |
| 主観的な選択 | 都合の良い方向、うまい具合に、特別な〜 | 何の条件を満たすのか不明 | 満たす条件を式で書く（「\( A\vec{v} = \lambda\vec{v} \) を満たす方向」） |
| 意味のない比喩語 | 特等席、魔法、秘密、鍵、心臓部、化ける | 数学的な意味がない | 該当する数学用語に置き換えるか削除 |
| 誇張 | 圧倒的、爆発的、劇的、驚くほど、瞬時に、強力な、複雑怪奇 | 根拠がなく検証できない | 回数・計算量・式で比較する（「行列積が \( n \) 回から \( 2 \) 回になる」） |
| 動作の比喩 | ドミノ倒しのように消える、解きほぐす、絡み合う | 何が起きるか曖昧 | 起きる計算を書く（「隣り合う \( P^{-1}P \) が \( I \) になる」「第1成分に \( y \) が入る」） |
| 結論の言い換え | 〜に他なりません、〜こそが本質です | 中身のない締め | 削除し、前の文で結論を明示する |
| 体験の誇張 | 体感する、肌で感じる | 何をするのか不明 | 「コードで計算結果を比較する」「アニメーションで確認する」 |
| 存在の曖昧化 | 〜が存在することがあります | 条件が書かれていない | 存在する条件・しない例を書く（「独立な固有ベクトルが \( n \) 本あれば対角化できる。\( \begin{pmatrix} 1 & 1 \\ 0 & 1 \end{pmatrix} \) はできない」） |
| 基底の省略 | 「\( A\vec{x} \) の係数は」「ベクトルの成分は」 | 何の基底に関する数値か不明 | 「固有ベクトル基底に関する \( A\vec{x} \) の係数は」「標準基底での成分は」のように基底を明記 |

「直感的なイメージ」「幾何学的な意味」と見出しに書く場合も、本文は上記の規則に従い、図形上で何が起きるか（どのベクトルが何倍になるか、どの成分にどの値が入るか）を具体的に書く。

## 3. 書き方の型

概念を説明する節は、原則として次の順で書く。

1. **問題:** 何が不便か・何を求めたいかを、具体的な式で示す（例: \( A\begin{pmatrix} x \\ y \end{pmatrix} = \begin{pmatrix} 2x + y \\ x + 2y \end{pmatrix} \) で成分が混ざる）。
2. **定義:** 新しい用語を式で定義する。
3. **具体例:** 定義を実際の数値に当てはめ、計算結果を示す。
4. **一般化と導出:** 一般の式を示し、なぜ成り立つかを途中式付きで導く（例: \( AP = (A\vec{v}_1\ A\vec{v}_2) = (\lambda_1\vec{v}_1\ \lambda_2\vec{v}_2) = PD \)）。
5. **検算:** 具体例で一般式と直接計算が一致することを示す。
6. **適用条件・限界:** 成り立たない場合、数値計算上の注意（桁あふれ・誤差）を書く。

効果・メリットを書く場合は「何の計算が、何回から何回になるか」「どの方程式が、どの形に変わるか」を式で示す。

## 4. リード文・学習目標・説明文

- **リード文:** 「この記事で扱う定義・式」と「それで何ができるか」を1〜2文で書く。比喩・誇張を入れない。
- **学習目標:** 「〜を説明できる」「〜を式で導ける」「〜を計算できる」など、達成を確認できる動詞で書く。「理解できる」「掴む」「体感する」は使わない。3項目にする（既存テストの前提）。
- **`src/content/articles.ts` の `description`・README:** 本文のリード文と内容を揃える。

## 5. 記法

- 1つの記事内で同じ文字を別の意味に使わない（例: 次数 \( n \) と累乗の指数を区別し、指数は \( k \) にする）。
- 数式は MathJax の `\( ... \)`（インライン）と `\[ ... \]`（ディスプレイ）で書く。
- 絵文字は使わず、アイコンは既存記事と同じ `svg.article-icon` を使う。

## 6. レイアウト・枠はみ出し防止規約（CSS・HTML）

記事内のコンテンツ（数式、タイトル、カード、コード、表）が親コンテナやボックスの枠線を右側にはみ出す（横オーバーフローする）ことを厳禁とする。次のルールを全記事のCSS・HTMLで遵守する。

### 6.1 数式（MathJax）のオーバーフロー防止
- 行列式や長い数式が `.definition-box`、`.theorem-box`、`.motivation-box`、`.tab-content` などの枠線を突き破らないよう、必ず `article.css` で以下を定義する：
  ```css
  mjx-container {
      max-width: 100% !important;
  }

  mjx-container[display="true"] {
      display: block !important;
      max-width: 100% !important;
      overflow-x: auto !important;
      overflow-y: hidden !important;
      -webkit-overflow-scrolling: touch;
      padding-block: 4px;
  }
  ```

### 6.2 タイトル英名の折り返し許可
- `.article-title__english` に `white-space: nowrap;` を指定してはならない。狭い画面幅や拡大表示時に親カードを突き抜ける原因となる。
- 必ず折り返しを許可し、モバイルではブロック要素として改行させる：
  ```css
  .article-title__english {
      display: inline-block;
      max-width: 100%;
      overflow-wrap: break-word;
      white-space: normal;
  }

  @media (max-width: 40rem) {
      .article-title__english {
          display: block;
          margin-top: 6px;
      }
  }
  ```

### 6.3 枠付きボックス・コンテナの防壁設計
- `.definition-box`, `.theorem-box`, `.motivation-box`, `.learning-goals`, `.highlight`, `.column`, `.source-card`, `.roadmap-card` などの枠線・背景付きボックスには必ず以下を指定する：
  ```css
  max-width: 100%;
  min-width: 0;
  box-sizing: border-box;
  overflow-wrap: break-word;
  ```
- フレックスやグリッドの子要素には `min-width: 0;` を明示し、子要素の内容による意図しない親幅拡張を防ぐ。

### 6.4 コードブロック・テーブル・画像
- `pre` には `max-width: 100%; box-sizing: border-box; overflow-x: auto; -webkit-overflow-scrolling: touch;` を指定する。
- インライン `code` には `max-width: 100%; overflow-wrap: break-word; word-break: break-word;` を指定する。
- テーブル要素には `display: block; max-width: 100%; overflow-x: auto; -webkit-overflow-scrolling: touch;` を指定する。
- 画像やキャンバスには `max-width: 100%; height: auto;` を指定する。

### 6.5 本文テキスト・見出し
- `p, li, dd, dt, h1, h2, h3, h4` に `overflow-wrap: break-word; word-break: break-word;` を指定し、長い英単語や数式記号での突き抜けを防ぐ。

## 7. セルフチェック（記事を書き終えたら必ず実行）

1. 次のコマンドで禁止表現が残っていないか確認する。ヒットした箇所は1つずつ書き換える。

   ```bash
   grep -nE "圧倒的|爆発的|劇的|驚く|瞬時|強力|秘密|魔法|特等席|観察|見つめ|乗り換え|都合|うまい具合|化け|ドミノ|複雑怪奇|解きほぐ|体感|に他なりません|本質" <対象ファイル>
   ```

2. 次のコマンドで枠はみ出しの原因となる `white-space: nowrap` が記事タイトルや本文に残っていないか確認する。

   ```bash
   grep -n "white-space:\s*nowrap" public/articles/**/*.css
   ```
   ※ `.tab-btn` などのボタン内でのみ許可し、`.article-title__english` や本文・ボックス要素には使用しないこと。

3. 各段落について、次の問いに文面だけで答えられるか確認する。答えられない段落は書き直す。
   - 主語（何が）と対象（何に）と結果（どうなる）は書かれているか。
   - 出てくる用語は、それより前で定義されているか。
   - 「係数」「成分」「座標」「表現行列」を書いたとき、何の基底に関するものかが明記されているか。
   - 主張に式または数値例が付いているか。
   - 数値例は手計算で検算して正しいか。
   - モバイル幅（375px〜400px）で表示した際、ディスプレイ数式やタイトルが枠線の右側にはみ出さず、適切にスクロールまたは折り返されているか。
4. 既存テスト（`tests/articles/`）・`npm test`・`npm run lint`・`npm run build` を実行し、すべて通ることを確認する。
